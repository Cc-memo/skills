# 问题生命周期与后续更新

仅在处理“以前出现过、当时未解决或后来方案变化”的问题时读取本文件。

## 单卡原则

- 同一症状、同一根因、同一解决策略演进：更新原问题卡，不按日期重复建卡。
- 同一症状但根因不同：创建新问题卡，并在“关联记录”说明差异。
- 原结论被证伪或旧方案已退出：保留旧记录，使用 `superseded_by` 或 `lifecycle_state` 标记，不删除历史。
- 每次实质处理仍创建独立会话；问题卡只汇总当前结论与关键时间线。

## 状态流转

```text
open -> investigating -> solved -> closed
  ^          |            |
  |          |            -> reopened（正文事件，frontmatter 改回 investigating）
  |          -> solved
  -> investigating
```

- `open`：只有现象，尚未形成可靠调查。
- `investigating`：已有排查与证据，但未完成验证。
- `solved`：根因、最终方案和验证结果均已确认。
- `closed`：问题长期稳定或不再适用。

## 更新动作

每次再次出现时：

1. 先运行两阶段召回，确认是否为同一问题。
2. 创建本次会话记录。
3. 原问题卡 `occurrences + 1`，更新 `updated`。
4. 在 `## 后续记录` 追加 `### YYYY-MM-DD — <事件>`，不得改写旧事件。
5. 未解决时保持 `open` 或 `investigating`；不要填写伪根因。
6. 已解决时填写 `root_cause`、`solution_type`、`resolved_at`、验证证据，并将 `review_state` 至少设为 `reviewed`。
7. 方案被替代时保留旧卡，通过 `superseded_by` 指向当前记录。

## 时间线格式

```markdown
## 后续记录

### 2026-08-05 — 首次发现

- 状态：investigating
- 摘要：首次复现，尚未确认根因。
- 会话：[[2026-08-05 - 排查某问题]]
- 验证：未完成。

### 2026-08-12 — 已解决

- 状态：solved
- 摘要：确认根因并完成修复。
- 根因：……
- 方案：……
- 会话：[[2026-08-12 - 解决某问题]]
- 验证：测试、运行结果或可复核证据。
```

## 合并门槛

只有以下内容一致时才合并：

- 核心现象或错误签名相同；
- 环境与适用范围兼容；
- 根因相同，或当前仍在验证是否同根因；
- 合并不会让两套互斥解决方案混在同一当前结论中。

不确定是否同一问题时，先写会话或 Inbox，不要立即改正式问题卡。
