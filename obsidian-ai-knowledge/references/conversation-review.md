# 对话复盘与问题暴露

调用 Skill 后，不把整段聊天直接当成问题记录。固定分成四层：

1. **对话总结**：目标、完成内容、决策、交付物、验证和遗留事项。
2. **问题候选**：从当前对话中提取实际出现的错误、阻塞、未解决事项或反复讨论的疑点。
3. **历史召回**：为每个问题候选组合症状、错误签名、技术、项目和根因关键词，先运行 `conversation_review.py`，内部使用 `recall_solution.py --mode cue --limit 3` 级别的低 Token 召回。
4. **处理决定**：
   - 命中同症状、同环境、同根因的问题卡：更新原问题卡并追加日期事件。
   - 只有相似会话或未验证线索：先保留为问题候选，验证后再晋升。
   - 没有历史命中：创建新问题卡或 Inbox 草稿，取决于是否已有根因和验证。

## 推荐输入

```json
{
  "conversation_title": "任务名称",
  "conversation_summary": "本次对话的事实摘要",
  "decisions": ["决定一"],
  "deliverables": ["变更文件或产物"],
  "open_questions": ["尚未解决的事项"],
  "problems": [
    {
      "symptom": "用户看到的现象或报错",
      "error_signature": "稳定错误文本，可为空",
      "technology": "涉及技术，可为空",
      "project": "项目名，可为空",
      "status": "investigating",
      "root_cause": "已确认才填写",
      "evidence": ["日志、测试或复现证据"]
    }
  ]
}
```

## 重要边界

- 总结记录回答“这次做了什么”。
- 问题候选回答“这次暴露了什么问题，以及以前是否解决过”。
- 没有根因和具体验证时，不得直接标记 `solved`。
- 只有在确认同一问题后，才调用 `update_problem.py --apply`。
- 当前检索是确定性的词法检索，不应描述成向量语义搜索。
